# Samus 2.1.1

## Release Theme

Add epistemic, causal, resilience, and control-efficiency capabilities by attaching them to existing platform seams rather than introducing parallel control systems.

## Motivation

The existing platform could rank alternatives and record outcomes, but it needed stronger answers to six questions:

1. Did an experimental arm actually improve over the incumbent?
2. How much reasoning is justified by the decision?
3. What claims does the system currently believe, and why?
4. Does the control loop respond safely under perturbation?
5. Is the controller oscillating?
6. Which workcell is accumulating organizational debt?

## Added

### Causal uplift

`backend/experiments/uplift.py` computes per-arm two-proportion uplift relative to an optional control arm and assigns a confounding-risk classification.

### Deliberation router

`backend/common/deliberation.py` maps value, urgency, uncertainty, and reversibility to a reasoning-depth ladder. It can escalate high-stakes, irreversible, uncertain decisions.

### Belief ledger

`backend/cognitive/belief_ledger.py` persists claims, evidence, counter-evidence, confidence, verification time, economic impact, tier, and status.

### Resilience benchmark

`backend/experiments/resilience.py` applies deterministic perturbations to the existing entropy and portfolio-control paths and records protective response quality.

### Control-loop friction

`backend/entropy/friction.py` measures decision flips and coordination cost from existing control-tick records.

### Organizational debt

`backend/governance/org_debt.py` combines trust, efficiency, and circuit-breaker state into a ranked workcell debt score.

## Architectural Significance

The release deliberately reuses:

- existing experiment arm statistics;
- existing LLM budget probes;
- existing triangulation outputs;
- existing control-loop functions;
- existing control-tick ledgers;
- existing workcell trust and circuit state.

This reduces duplicate state and preserves one source of truth per concern.

## Validation

The legacy architecture narrative reports an increase from 5,392 to 5,442 passing tests at release time. Treat that as historical release evidence, not a current-suite result. Re-run the suite in the target environment before publishing.

## Rejected Design

Runtime ontology mutation was rejected because arbitrary labels and schema changes would weaken graph security guarantees. New concepts should be surfaced as insights over existing nodes until a reviewed schema change is approved.

## Deferred Work

- Operational thresholds require production calibration.
- Promotion gating remains opt-in.
- The deliberation router is advisory unless a caller explicitly adopts its decision.
- Benchmark scenarios are deterministic and do not prove resilience under all real failures.
